# 캡차 서비스 — 쿠버네티스 매니페스트

옛 GPU 서버에서 돌던 캡차를 쿠버네티스로 옮기기 위한 설정 파일이다.

```
00-namespace.yaml      catchap 네임스페이스
10-configmap.yaml      비밀이 아닌 설정
20-secret.예시.yaml     ★예시일 뿐. 실제 값은 명령으로 만든다
30-deployment.yaml     파드 2벌
40-service.yaml        클러스터 안 주소
50-ingress.yaml        captcha.catchap5.com → 서비스
```

적용 순서는 파일 이름의 번호 순이다.

---

## 값은 어디서 왔나

★**추측한 값이 없다.** 옛 GPU 서버에서 **지금 돌고 있는 프로세스의 환경변수를 직접 읽어**
왔다. 다만 아래 넷은 **일부러 바꿨고**, 왜 바꿨는지 적어 둔다.

| 항목 | 옛 서버 | 여기 | 왜 |
|---|---|---|---|
| `DB_HOST`·`DB_NAME`·`DB_USER` | `10.0.1.168` / `captcha_ms` / `captcha_gpu_app` | `10.0.2.193` / `catchap_captcha` / `catchap_captcha_app` | 관리형 MySQL 로 이전하며 이름도 바로잡음 |
| ★`BEHAVIOR_AI_URL` | `http://127.0.0.1:8010` | 서비스 이름 | 옛 서버는 캡차와 행동AI가 **같은 서버**에 있었다. 쿠버네티스에서는 다른 파드다 |
| ★`ALLOWED_ORIGINS` | `*` | `catchap5.com` 두 개 | `*` 는 **아무 사이트나 이 캡차를 부를 수 있다**는 뜻이다. 이전을 기회로 좁힌다 |
| `DB_UNIX_SOCKET` | 로컬 소켓 경로 | **뺐다** | `db.py` 는 호스트가 `localhost` 일 때만 소켓을 쓴다. 여기선 안 쓰이지만, 없는 파일을 가리키는 설정은 다음 사람을 헷갈리게 한다 |

---

## ★확인하면서 알게 된 것 3가지

### ① 검증 요청마다 디스크에 파일을 쓴다

`app/main.py:846` 이 요청마다 `data/runtime/behavior-events/…/{id}.json` 을 만든다.
옛 서버에 **13일 동안 1,122개 · 9MB** 쌓여 있고 **지우는 코드가 없다.**

**읽는 코드는 없다** — 쓰기 전용이다(DB 에는 파일 경로만 적힌다). 그래서 파드마다
따로 둬도 동작에는 문제가 없다. `emptyDir` 로 붙였다.

⚠️**두 가지는 남는다** — 파드가 죽으면 그 파일들은 사라지고, DB 에 적힌 경로를 나중에
따라가려 하면 **어느 파드에 있는지 알 수 없다.** 지금 그 파일을 읽는 기능이 없으니
당장 문제는 아니지만, **읽는 기능을 만들 거라면 Object Storage 로 보내야 한다.**
→ ms 님께 알릴 것.

### ② 안 쓰는 코드가 디스크 쓰기를 하고 있었다

`app/captcha.py` 의 `render_challenge`·`render_object_challenge` 는 문제 이미지를
디스크에 저장한다. **어디서도 부르지 않는다.** 지금 문제 이미지는 이미지 안에 구워 둔
`data/final` 에서 바로 나간다(`main.py:706`).

★이걸 확인 안 했으면 **"2벌로 띄우면 이미지가 안 보인다"** 고 잘못 판단할 뻔했다.
`CHALLENGE_DIR` 이라는 환경변수가 아직 설정돼 있어서 더 그랬다.

### ③ 기동할 때 스키마를 만든다

`db.py:289` 가 `GET_LOCK` 을 잡고 테이블을 만든다. **두 벌이 동시에 떠도 안전**하다
(먼저 잡은 쪽이 만들고 나머지는 기다린다). 그래서 `catchap_captcha_app` 에 DDL 권한을
줬다. 자세한 이야기는 `인프라-캡처/91-팀공유/01-캡차-스키마방식-ms님.md`.

준비가 늦어질 수 있어 `startupProbe` 로 최대 2분 기다리게 했다.

## 어디까지 검증했나

| | 결과 |
|---|---|
| YAML 문법 | ○ 6개 파일 파싱 성공 |
| 라벨·셀렉터가 이어지나 | ○ Deployment ↔ Service ↔ Ingress |
| 포트 이름이 이어지나 | ○ `http` |
| ConfigMap·Secret 참조 | ○ |
| 볼륨 이름·마운트 지점 | ○ `RUNTIME_DIR` 과 일치 |
| 이미지 태그가 `latest` 가 아닌가 | ○ 커밋 해시 |
| ★**쿠버네티스 스키마 검증** | ✗ **못 했다** |
| ★**실제 적용** | ✗ **못 했다** |

★**스키마 검증을 못 한 이유** — `kubectl --dry-run=client` 도 서버에서 API 목록을
받아와야 하는데 kubeconfig 가 없다. apiserver 의 `/openapi/v2` 도 **403** 이다
(`/version` 은 익명 200 인데 스키마는 막혀 있다).
**필드 이름 오타 같은 것은 아직 못 걸렀다.** 클러스터 권한을 받으면 가장 먼저 할 일이다.

---

## 적용 전에 있어야 하는 것 4가지

```
① 클러스터 권한 (cluster-admin)        ← 지금 막혀 있는 것
② CR 저장소 catchap-captcha-repo       ← 아직 없음. 이미지를 올릴 곳
③ 인그레스 컨트롤러                     ← 클러스터에 아직 없음
④ captcha.catchap5.com DNS 레코드      ← 아직 없음
```

그리고 **behavior-ai 를 먼저 배포**해야 `BEHAVIOR_AI_URL` 이 실제로 뜬다.
캡차만 먼저 올리면 행동 판별 호출이 실패한다.

## 시크릿 만드는 법

값을 파일에 남기지 않는 방법으로 만든다. `20-secret.예시.yaml` 의 주석 참고.

★**컷오버 때 회전을 권한다** — `APP_SECRET`·`CAPTCHA_SITE_SECRET` 등이 옛 GPU 서버의
프로세스 환경에 평문으로 남아 있고, 그 서버는 인터넷에 열려 있다.
