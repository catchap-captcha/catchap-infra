## 요약

**`catchap-redis-prod` 를 삭제하고 `catchap-valkey-prod` 를 새로 만들었습니다.**
사용자 인증이 꺼져 있었는데, 그 설정은 만들 때만 정할 수 있기 때문입니다.
아래에 근거를 정리했습니다.

| | |
|---|---|
| 지운 것 | `catchap-redis-prod` (2026.07.28 생성 · 데이터 0건) |
| 만든 것 | `catchap-valkey-prod` (2026.08.03 14:27 생성) |
| 사양 | **동일** — Valkey 8.1.0 · t1i.small × 2노드 · 같은 VPC/서브넷/보안그룹 |
| 달라진 것 | **사용자 인증 ON · 전송 암호화(TLS) ON** · 이름 정정 |

## 1. 무엇이 문제였나

기존 클러스터는 **사용자 인증과 전송 암호화가 둘 다 꺼진 상태**였습니다.

```
접근 제어
  사용자 인증        미사용
  전송 암호화(TLS)    미사용
```

즉 **VPC 안에 들어온 누구나 비밀번호 없이 붙어서 데이터를 읽고 지울 수 있는** 상태였습니다.
실제로 VM1에서 붙어 보니 `PING` 에 `+PONG` 이 그냥 돌아왔습니다.

지금은 데이터가 없어 위험이 없었지만, 저희가 여기에 넣으려던 데이터가
**캡차 토큰 재사용 차단 기록**이라 문제가 됩니다. 그 기록을 지울 수 있으면
**한 번 쓴 캡차 토큰을 다시 쓸 수 있게** 됩니다.

---

## 2. 왜 고치지 않고 다시 만들었나

**사용자 인증은 클러스터를 만들 때만 정할 수 있고, 만든 뒤에는 켤 수 없습니다.**
세 곳을 확인했고 전부 같은 결론이었습니다.

| 확인한 곳 | 결과 |
|---|---|
| 콘솔 클러스터 상세의 액션 버튼 | 자동 백업 설정 · 백업 생성 · 파라미터 그룹 변경 · 보안 그룹 수정 · 노드 유형 변경 — **접근 제어를 바꾸는 메뉴가 없음** |
| 콘솔 클러스터 **생성** 마법사 | **3단계 「고급 설정 — 접근 제어」** 에 있음 = 생성 시 설정 |
| [MemStore API 문서](https://docs.kakaocloud.com/en/service/data-store/memstore/api/memstore-api-common) | 클러스터 관련 엔드포인트가 **조회 5개 + 파라미터그룹 재적용 1개**뿐. **수정(PUT/PATCH) 엔드포인트가 없음** |

서비스 계정의 역할을 생성 후에 못 바꾸는 것, Secrets Manager 시크릿의 이름을
생성 후에 못 바꾸는 것과 같은 구조였습니다.

---

## 3. 잃은 것이 없다는 근거

지우기 전에 **세 가지를 직접 확인**했습니다.

```
① DBSIZE = 0            Primary·Replica 둘 다. 저장된 키가 하나도 없음
② keyspace 비어 있음      INFO keyspace 에 db0 조차 안 나옴
③ 자동 백업 6개의 파일 크기 = 175 Bytes   (담긴 데이터가 없다는 뜻)
④ 모니터링 1시간          get · set · del 호출 전부 0회
                        활성 커넥션 2개 = 복제와 헬스체크뿐
```

코드에서도 이 주소를 참조하는 곳이 **0곳**입니다. 앱은 세션·시도제한·잡 상태를
전부 MySQL에 두고 있어 MemStore를 쓴 적이 없습니다.

**한 번도 쓰이지 않은 빈 클러스터였습니다.**

---

## 4. 순서를 「만들고 나서 지우기」로 했습니다

지우고 만들다가 생성이 막히면(권한·쿼터) **서비스가 사라진 채로 남습니다.**
반대로 하면 실패해도 잃는 것이 없습니다.

```
① 새로 만든다 (인증 ON · TLS ON)     14:27:51
② 실제로 붙어서 검증한다
③ 그 다음에 옛것을 지운다
```

실제로 두 클러스터가 문제없이 공존했습니다. 만약 쿼터가 1개였다면
**아무것도 잃지 않은 채로** 그 사실을 알고 순서를 바꿨을 것입니다.

---

## 5. 검증 — 콘솔 표시가 아니라 실제로 붙어서 확인했습니다

VM1(210.109.82.148)을 거쳐 사설망 노드에 직접 붙었습니다.
비밀번호는 스크립트 안에서만 읽어 쓰고 명령줄·로그에 남기지 않았습니다.

**대조군을 먼저 봤습니다** — 옛 클러스터에 평문으로 `PING` → `+PONG`.
이게 나와야 제 시험 방법이 정상이라는 뜻입니다.

| 시험 | 결과 |
|---|---|
| 평문 접속 | **응답 없음** — TLS 필수 |
| TLS + `PING` (인증 안 함) | **`-NOAUTH Authentication required.`** |
| TLS + `AUTH` → `PING` → `DBSIZE` | `+OK` → `+PONG` → `:0` |
| TLS + **틀린 비밀번호** | **`-WRONGPASS invalid username-password pair`** |
| 인증 없이 `DBSIZE` (데이터 명령) | **`-NOAUTH`** |

**Primary와 Replica를 따로 시험했습니다** — 복제본만 인증이 빠져 있는 경우가 있어서입니다.
둘 다 같은 결과였습니다.

### TLS 인증서까지 확인했습니다

콘솔에서 받은 `ca.crt` 로 서버 인증서를 검증해 봤습니다.
서버 인증서는 **CA 인증서 그 자체**였습니다 — 자기서명이고 `subjectAltName` 이 없으며
`CN=service.kakaoenterprise.com` 입니다. 우리 엔드포인트 이름이 인증서에 없습니다.

앱이 쓸 설정을 **양방향으로** 확인해 정했습니다.

| 설정 | 결과 |
|---|---|
| `cafile=ca.crt` · **`check_hostname=True`** · `server_hostname="service.kakaoenterprise.com"` | **통과** · TLSv1.3 · `TLS_AES_256_GCM_SHA384` |
| 같은 설정 · `server_hostname="wrong.example.com"` | **거부** — `Hostname mismatch` |
| `server_hostname` 은 맞지만 **가짜 CA** | **거부** — `CERTIFICATE_VERIFY_FAILED` |
| `server_hostname=` 엔드포인트 주소 | **거부** — 인증서에 그 이름이 없음 |

★**요령은 `server_hostname` 에 엔드포인트가 아니라 인증서의 CN 을 넣는 것**입니다.
SAN 이 없을 때 OpenSSL 이 CN 으로 대조하기 때문에 통과합니다.
**검증을 끄지 않아도 됩니다.**

★처음에는 엔드포인트 주소로 붙어 보고 거부되니까 *"호스트명 검증은 구조적으로 불가능"* 이라
판단해 `check_hostname=False` 로 쓰려 했습니다. **제시하는 이름을 바꾸면 된다**는 것을
나중에 찾아 고쳤습니다. 검증을 낮추지 않아도 됩니다.

남는 한계는 이것입니다 — 카카오가 **모든 MemStore 클러스터에 같은 정적 인증서**를
쓰는 것으로 보여, **"이 호스트가 우리 클러스터냐" 는 인증서만으로 구분하지 못합니다.**
다만 그러려면 이미 VPC 안에 들어와 있어야 하고 비밀번호도 따로 필요해,
수용 가능한 잔여 위험으로 판단했습니다.

## 7. 그런데 MemStore를 지금은 쓰지 않습니다

같이 보고드립니다. **앱이 이미 무상태였습니다.**

처음에 저는 "로그인 정보가 앱 메모리에 있어 재시작하면 전원 로그아웃될 것"이라고
팀 설계 문서에 적었는데, **코드를 열어 보니 틀렸습니다.** 흔한 문제라서
확인 없이 적었습니다.

| 서버에 남을 법한 것 | 실제 위치 |
|---|---|
| 로그인 세션 | JWT + DB `refresh_tokens` |
| 캡차 문제·정답 | 암호화해서 토큰 안에 (서버에 안 남음) |
| 토큰 재사용 차단 | DB `captcha_consumed_tokens` (UNIQUE 제약) |
| 로그인 시도 제한 | DB `login_throttle` |
| 문항 생성 잡 | DB `lecture_question_gen_jobs` |
| 모듈 수준 가변 상태 | **0건** |

코드 주석에 이유까지 있었습니다.
> *"무상태 서명 토큰의 리플레이 차단은 인메모리로는 멀티워커/재시작에 무효
>  → (kind, token_id) UNIQUE로 원자적 소비"*

**그래서 이번 이전에서 실제로 옮길 것은 미디어 3.3GB와 데이터베이스 둘뿐이었습니다.**

그럼에도 클러스터를 **반납하지 않고 인증을 켜서 다시 만든** 이유는,
나중에 쓸 자리가 분명하고 그때는 인증을 켤 수 없기 때문입니다.

★쓸 자리 — `captcha_consumed_tokens` 가 지금 **29,001행 · 14MB** 쌓여 있습니다.
수명이 몇 분인 데이터인데 **지우는 코드가 없어** 계속 늘고 있습니다.
Valkey라면 `SET ... EX 300` 한 줄로 끝나고 청소 코드가 필요 없습니다.
지금 규모에서는 MySQL로 충분해 미뤄 두었고, 우선 **청소 코드를 넣을 계획**입니다.

## 8. 남긴 기록

단계마다 **콘솔이 준 기본값**과 **저희가 바꾼 값**을 따로 기록했습니다.
나중에 *"이 값이 왜 이렇지"* 를 물었을 때 둘이 구분되도록 하기 위해서입니다.

실제로 그 덕에 하나 잡았습니다 — **백업 보존 기간 기본값이 7일**인데
기존 클러스터는 14일이었습니다. 그냥 넘겼으면 백업 보관 기간이 절반으로 줄었을 겁니다.

TLS 인증서(`ca.crt`)와 앱에서 쓸 설정·한계도 같이 정리해 두었습니다.
