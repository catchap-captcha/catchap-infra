### 1-3. ★어제 새벽 — 입구 이중화 (7/31 미해결 과제)

7/31 점검에서 **"워커1 서버가 죽으면 서비스가 끊긴다"** 가 남아 있었습니다. 해결했습니다.

```
전   로드밸런서 1대 (가용영역 2-a)        →  2-a 가 죽으면 전체 중단
후   로드밸런서 2대 + 고가용성 그룹        →  한쪽이 죽어도 반대쪽이 받는다
```

두 번째 가용영역(2-b)에 로드밸런서·대상 그룹·리스너를 새로 만들고, 둘을 고가용성 그룹으로
묶었습니다. **인증서(HTTPS)도 양쪽에 동일하게 붙였습니다.**

### 1-4. 도메인 전환 방식 확정

고가용성 그룹이 **IP 가 아니라 DNS 이름**을 주기 때문에, 전환은 A 레코드 교체가 아니라
**CNAME 연결**입니다. 가비아에서 고칠 레코드는 3~4줄이고, **되돌리는 데 10분**입니다.

```
www · api      CNAME  →  고가용성 그룹 주소
루트 도메인     A 레코드 2개 (루트는 규격상 CNAME 을 못 씀)
메일 관련 레코드는 건드리지 않습니다
```

### 1-5. 자원 이름 표준화 (완료)

이름만 보고 무엇인지 알 수 있게 정리했습니다.

```
로드밸런서   LoadBalancer01  →  catchap-lb-2a  ·  catchap-lb-2b  ·  catchap-lb-2ab
서브넷       안 쓰는 것 2개 삭제 후 4개 이름 통일
             catchap-core-2a · catchap-core-2b · catchap-gpu-2a · catchap-jump-2a
```

★**이름에 「역할 + 가용영역」이 들어갑니다.** 정렬하면 이중화 짝(`core-2a`·`core-2b`)이
위아래로 붙어 구조가 눈에 보입니다.

### 1-6. ★배포 — 화면(프론트엔드)이 새 환경에서 동작합니다

```
인그레스 컨트롤러   서버 2대에 하나씩 · 입구에서 들어온 요청을 앱으로 나눠 줌
화면(프론트엔드)   2벌 · ★서로 다른 가용 영역에 하나씩
주소 규칙         루트 도메인 → www (경로까지 그대로 유지)
```

**확인 방법** — 실제 요청을 보내 응답을 확인했습니다.

```
www.catchap5.com/            200   제목이 우리 서비스 것으로 나옴
www.catchap5.com/courses/3   200   내부 페이지 새로고침도 정상
catchap5.com/courses/3       308   www 로 넘어가며 경로 유지
```

## 4. ★막혀 있던 쿠버네티스 배포 권한 — 오후에 저희가 풀었습니다

**오전 점검 때 「요청드린 상태」로 말씀드렸는데, 오후에 원인을 찾아 해결했습니다.
강사님께서 해 주실 일은 없습니다.**

**원인은 권한이 아니라 저희가 쓰던 계정이었습니다.**

```
운영용 서비스 계정으로 접근    403
★사용자 계정으로 접근         200
```

7월 30일부터 **서비스 계정 하나로만 시험**하고 있었습니다. 그 계정은 조회 권한만 있어
거절당한 것이었는데, **거절 메시지에 계정 이름이 찍혀 있는 것을 뒤늦게 확인**하고
사용자 계정으로 다시 재 보니 **바로 통과했습니다.**

**해결한 방법**

```
① 사용자 계정 자격 증명을 임시로 발급해 확인          → 통과
② 배포 전용 서비스 계정을 클러스터 관리자 명단에 추가   → 통과
③ 그 서비스 계정만으로 다시 확인                     → 통과
④ 임시 자격 증명 삭제
```

★**②를 한 이유** — ①만으로도 배포는 되지만 **개인 계정에 의존하게 됩니다.**
사람이 빠지면 배포가 멈추고, 누가 했는지도 기록에 안 남습니다.
**배포는 전용 계정으로만** 하도록 옮겨 두었습니다.

★**같이 확인한 것** — 권한을 얻은 뒤 클러스터 상태를 점검했습니다.
**노드 2대가 서로 다른 가용 영역에서 정상**이고, 저희가 준비한 배포 설정이 전제로 삼은
**영역 구분 표시도 실제로 붙어 있었습니다.** 이게 없으면 앱이 조용히 안 뜹니다.

## 6. 오늘 배운 것 하나 — 팀에도 공유했습니다

★**거절 응답에 「누가 거절당했는지」가 적혀 있습니다.**

닷새 동안 「권한이 없다」로 알고 있었는데, 응답 본문을 열어 보니
**거절당한 계정 이름이 그대로 찍혀 있었습니다.** 그걸 보고 나서야
**시험에 쓰던 계정이 문제라는 것**을 알았습니다.

**「무엇이 실패했나」뿐 아니라 「누구로 시도했나」를 같이 봐야 한다**는 것을
이번에 확실히 배웠습니다. 같은 이유로, 오늘은 무엇을 확인하든
**바꾸지 않은 쪽을 같이 재는 방식**으로 판정했습니다.
