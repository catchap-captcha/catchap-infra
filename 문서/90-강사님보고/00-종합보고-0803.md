★★**아래 요청은 철회합니다.** 0804 에 원인을 찾았습니다 —
**권한이 없던 게 아니라 저희가 서비스 계정으로만 시험하고 있었습니다.**

```
catchap-ops (서비스 계정)     /api/v1/namespaces   403
★사용자 계정                  /api/v1/namespaces   200
```

거절 응답 본문에 **`User "catchap-ops-…@kc.serviceaccount.com" cannot list …`** 라고
**계정 이름이 찍혀 있었는데**, 그 본문을 0804 에야 열어 봤습니다.
사용자 계정으로 재니 **강사님 클러스터도 바로 통과**했습니다.

**해결 방법** — 사용자 계정으로 들어가 `catchap-ci` 서비스 계정을 `cluster-admin` 에
바인딩하고, **그 서비스 계정만으로 200 을 확인**한 뒤 임시 자격 증명을 지웠습니다.
개인 계정 의존을 남기지 않기 위해서입니다.

★**교훈 = `403` 은 「권한이 없다」가 아니라 「이 신원에 권한이 없다」이다.**
**무엇이 실패했나 못지않게 누구로 시도했나를 봐야 한다.**

아래는 그때의 기록으로 남겨 둡니다.

```
인증 없이   /api/v1/namespaces   403
IAM 토큰    /api/v1/namespaces   403        ← ★이 IAM 토큰이 catchap-ops 것이었다
```

★인그레스 컨트롤러 배포에도 ClusterRole이 필요해서, 카카오 문서도 `cluster-admin`을
전제로 하고 있었습니다. **이제 `catchap-ci` 로 설치할 수 있습니다.**
