## 실행 위치 — ★저희 점프서버에 준비해 뒀습니다

**클러스터 엔드포인트가 프라이빗이라 사무실 PC·인터넷에서는 접속이 안 됩니다.**
`Team1-VPC` 안에서 실행하셔야 합니다.

```
apiserver   https://04c32b21-7670-4cd9-b970-aecc2f648343-internal.ke.kr-central-2.kakaocloud.com
            ★-internal 주소 — VPC 밖에서는 DNS 조차 안 잡힙니다
```

**저희 점프서버에 `kubectl` 을 미리 설치해 두고, 실제로 apiserver 에 닿는 것까지 확인했습니다.**

```
점프서버      ubuntu@210.109.82.148        공인 IP · SSH 22 열림
kubectl      v1.33.5 설치 완료             클러스터와 같은 버전 · 체크섬 검증함
apiserver    DNS ✅ 10.0.6.35 · 10.0.2.141  (HA 2대)
             443 ✅ 연결됨 · /version 200
```

**말씀해 주시면 계정을 만들어 두겠습니다.** 접속하셔서 위 명령 한 줄만 치시면 됩니다.

VPC 안 다른 VM 을 쓰셔도 됩니다. `kubectl` 이 없으면 이렇게 설치합니다.

```bash
curl -LO "https://dl.k8s.io/release/v1.33.5/bin/linux/amd64/kubectl"
sudo install -m 0755 kubectl /usr/local/bin/kubectl
```

kubeconfig 는 콘솔에서 받습니다 — `Container Pack → Kubernetes Engine → catchap-cluster-prod`.
(저희는 IAM 토큰으로 붙었기 때문에 kubeconfig 없이도 접속은 됩니다.)

## 왜 이건 저희가 못 하나요

**Kubernetes 권한은 클러스터 내부 RBAC 이고, 카카오클라우드 IAM 역할로는 대체가 안 됩니다.**
Kubernetes 는 **전용 IAM 역할이 아예 없습니다**(IAM 역할 37개를 전수 확인했습니다).

실제로 `프로젝트 관리자` 를 받은 뒤에도 클러스터 API 는 여전히 막혀 있습니다.
**오늘 점프서버에서 직접 호출해 확인한 응답**입니다.

```
GET /api/v1/namespaces   (catchap-ops IAM 토큰)

  "namespaces is forbidden: User \"catchap-ops-kc-sfacspace05@kc.serviceaccount.com\"
   cannot list resource \"namespaces\" in API group \"\" at the cluster scope"
  code: 403
```

★**apiserver 가 저희를 이름으로 알아봅니다.** `401`(누구인지 모름)이 아니라 `403`(누군지는
알지만 권한 없음)입니다. 즉 **인증은 이미 되고 권한만 없습니다** — kubeconfig 를 받아도
해결되지 않고, 위 `clusterrolebinding` 한 줄이 있어야 합니다.

## 왜 `edit` 이 아니라 `cluster-admin` 인가요

인그레스 컨트롤러 배포 YAML 이 **클러스터 범위 리소스**를 만듭니다.

```
Namespace · ClusterRole · ClusterRoleBinding · IngressClass · ValidatingWebhookConfiguration
```

`edit` 은 네임스페이스 안쪽만 다룰 수 있어 이 리소스들에서 막힙니다.

## 다른 조에 영향이 있나요 — 없습니다

이 클러스터는 **1조 전용**입니다. 워커 2대(`10.0.2.128`·`10.0.6.202`)가 모두 `Team1-VPC` 에
있고, 다른 조 자원은 이 클러스터에 없습니다. K8s 권한은 **클러스터 안으로만** 미치므로
다른 프로젝트·다른 조에는 닿지 않습니다.

## 같이 주시면 좋은 것 (없어도 됩니다)

**클러스터 CA 인증서** — kubeconfig 의 `certificate-authority-data` 입니다.
지금은 이게 없어서 TLS 체인 검증을 못 하고 **서버 인증서 지문 2개를 고정**해 쓰고 있습니다
(apiserver 가 HA 2대라 지문이 2개입니다). 있으면 정석대로 검증할 수 있습니다.

값을 0 으로 적어 두고** 그걸 근거로 삭제를 요청드렸습니다.

오늘 `catchap-backend` 서비스 계정(이 시크릿의 접근 명단에 든 계정)으로 API 를 부르니

즉 **강사님이 저희 DB 접속 정보를 넣어 두신 것으로 보입니다.** 미완성이 아닙니다.
**삭제 요청을 철회합니다.** 저희가 쓸 이름은 다른 것으로 정하겠습니다.
