| **무엇을** | 클라우드에만 있고 **GitHub 에는 없던 것**을 저장소로 옮김 |

## 1. 판단 기준 — 무엇을 넣고 무엇을 안 넣나

넣을지 말지는 **크기가 아니라 「다시 만들 수 있나」**로 갈랐습니다.

```
① 코드로 다시 만들 수 있다        → ★안 넣는다 (컨테이너 이미지, 파이썬 가상환경)
② 인터넷에서 다시 받을 수 있다     → ★안 넣는다 (공개 데이터셋 — 주소만 적어 둔다)
③ 다시 만들 수 없다               → ★넣는다   (사람이 만든 자산, 손으로 쌓은 설정)
④ 넣으면 안 된다                  → ★절대 안 넣는다 (자격증명, 개인정보)
```

⚠️**④가 ③보다 우선합니다.** 되살리기 편하자고 자격증명을 저장소에 넣으면,
그 순간 저장소가 유출 경로가 됩니다.

## 2-2. ✅아카이브 28,537개는 안 옮깁니다 (2026-08-12 결정)

「옛 버전이니 아마 필요 없을 것」이 아니라, **재서 확인하고 결정했습니다.**

### 아카이브가 무엇인가

캡차 조각을 **오려내는 방식이 0810에 바뀌었고**, 그 전에 만들어 둔 조각들입니다.

```
옛것  네모(사각형)로 뚝 잘라냄   → 벽·바닥·소파가 같이 딸려 옴
지금  ★사람 윤곽대로 오려냄       → 배경이 빠지고 사람만 남음  (SAM2 모델)
```

코드에 그대로 있습니다 — `refine_mask_fallbacks_sam.py` 가 `method == "rectangle"`
(네모로 잘린 것)만 골라 다시 오려냅니다.

### 전수 비교 — 아카이브에만 있는 파일은 ★0개

```
아카이브 28,537개
  ├ 19,569개  지금 것과 ★내용까지 완전히 같음 (ETag 일치)  → 버려도 손실 0
  └  8,968개  네모로 잘렸던 옛 버전                        → 새 버전이 있음
★아카이브에만 있는 이름  0개
지금에만 있는 것        6,005개 (0810 이후 새로 만든 것)
```

### 지금 쓰이지 않는다 — 세 군데에서 확인

```
① 설정   ASSET_KEY_PREFIX = captcha-service/final
         앱은 모든 키 앞에 ★이것만 붙인다 (asset_storage.py:135)
         → archive 프리픽스는 ★주소를 만들 방법이 없다
② 코드   asset_storage·captcha·config·main 에 "archive" ★0번
         게다가 `data/final` 밖으로 나가는 키를 ★막는 검사가 있다
③ 데이터  DB 6,903문제(active 2,003) 전수 → 경로에 archive 든 것 ★0건
         실제 값은 images/auto_00001.jpg · pieces/legacy_gd_001-target_1.png
```

★**「안 쓰는 것 같다」가 아니라 「쓸 수가 없다」**까지 확인한 뒤 버리기로 했습니다.

## 3. ✅한 일 — 캡차 자산 2.05GB

```
어디에   catchap-captcha 저장소 · Release  assets-20260812
무엇을   final/images   6,904개  499MB   배경 이미지

확인     서버에서 잰 SHA256 과 받은 쪽 값이 ★4개 모두 일치
```

★**`*.jsonl` 이 이미지보다 중요합니다.** 이미지가 다 있어도 이 목록이 없으면
**어떤 조각이 어느 문제의 정답인지** 알 수 없습니다.

### ★여기서 하마터면 틀릴 뻔한 것

처음에 **「28,545개가 이 서버에만 있는 유일본」**이라고 적었습니다. 틀렸습니다.

```
제가 센 것    captcha-service/final 프리픽스만 → 41,446
실제          + captcha-service/archive-0810-… → 28,537
                                        합계 → 69,983 = ★로컬 이미지 전부
```

★**프리픽스 하나만 세고 「나머지는 없다」고 읽었습니다.**
0810 에 민서님이 아카이브까지 전부 올려 두셨습니다.
→ 규칙: **「없다」고 말하기 전에 ★어디까지 셌는지**를 먼저 본다.

## 4. 🚫DB 데이터를 저장소에 넣지 않는 이유

`catchap` 100개 표에는 **실제 사용자의 이메일·이름·학습기록**이 들어 있습니다.
저장소가 비공개여도 넣지 않습니다.

```
저장소는 ★한 번 넣으면 커밋 이력에 영원히 남습니다.
나중에 지워도 옛 커밋에는 그대로 있습니다.
협업자를 한 명 추가하는 순간 그 사람도 전부 볼 수 있습니다.
```

★**대신 이렇게 합니다** — 표 구조(alembic)는 저장소에 있으므로,
새 DB 를 만들고 마이그레이션을 돌리면 **빈 서비스가 정상 기동**합니다.
사용자 데이터가 필요하면 그때 별도 경로로 옮깁니다.

⬜**단, `catchap_captcha` 의 문제은행은 이야기가 다릅니다.** 개인정보가 아니라
민서님이 만든 자산입니다. → 6절

## 5. ⚠️아직 「코드로」 되지 않는 것

```
VPC·서브넷·보안그룹·로드밸런서·관리형 MySQL·MemStore·IAM·레지스트리
  → 전부 ★콘솔에서 손으로 만들었습니다. Terraform 같은 정의 파일이 없습니다.
  → 지금은 ★문서(95-0811-최종상태/)와 캡처로만 남아 있습니다.
```

★**심사에서 물어보면 이렇게 답합니다** — *"클러스터 안(쿠버네티스)은 전부 코드로
저장소에 있습니다. 클러스터 밖 클라우드 자원은 콘솔로 만들었고, 대신 어떤 값으로
만들었는지를 문서와 캡처로 남겼습니다. 코드화는 다음 단계입니다."*

숨기지 않고 **어디까지 되고 어디부터 안 되는지**를 말하는 편이 낫습니다.

## 5-2. ✅저장소에 없던 소스 26개도 옮겼습니다

자산만으로는 부족했습니다. **코드에도 구멍이 있었습니다.**

어디에   catchap-records/옛-GPU-서버-작업물/   (커밋 43e416c)

★**「코드는 당연히 GitHub 에 있겠지」가 사실이 아니었습니다.** 목록으로 대조해야
알 수 있는 것이었습니다.

## 6-2. ⚠️★못 가져온 것 하나 — 라벨링 폴더의 `*.jsonl` 147MB

**같은 실수를 반복할 뻔했습니다.** `data/final` 에서 배운 것이 있습니다.

```
★이미지는 다시 만들 수 있고, ★결정은 다시 만들 수 없다.
   data/final  이미지 41,446장 + jsonl 8개
               → ★jsonl 이 없으면 어떤 조각이 어느 문제의 정답인지 모른다
```

`data/labeling` 3.9GB 도 똑같은 구조입니다.

```
tallyqa_complex_30000/  3.4GB · 파일 60,431개  ← 잘라 낸 이미지. ★스크립트로 다시 만듦
★*.jsonl               147MB                  ← ★사람이 고르고 번역한 결과
```

★**147MB 쪽이 진짜입니다.** 그런데 **이번에 안 가져왔습니다.**
(자산 2.05GB 와 소스 26개를 챙기고 서버를 껐습니다.)

### 어떻게 할까

```
가져오려면   옛 GPU 를 ★한 번 더 켜야 합니다 (IP 붙임 → 받기 → IP 뗌 → 끔)
크기         147MB — 받는 데 1분이면 됩니다
★권합니다    민서님 답이 오면 ★그때 한 번에 같이 받는 것이 낫습니다
             (켰다 끄는 것을 두 번 하지 않게)
```
