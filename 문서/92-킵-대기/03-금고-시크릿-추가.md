## ★왜 하나로 안 묶고 둘로 나누나

처음에 `catchap-backend-extra` 하나에 3개를 넣으려 했는데 **사장님이 「원래 각각
만드는 거 아니었어?」 라고 하셔서 되돌렸습니다. 맞습니다.**

기존 5건은 **하나가 하나의 용도**입니다.

```
catchap-auth-jwt-secret       로그인 서명
catchap-smtp-app-password     메일
catchap-stt-worker-token      자막
catchap-metrics-ingest-token  모니터링
catchap-portone-keys          결제  ← ★값이 2개지만 같은 용도라 한 통
```

★**회전 때문에 중요합니다.** S3 키는 **0803 에 이미 한 번 회전**했습니다. DB URL 과
묶어 두면 S3 키만 바꿀 때도 **DB 비밀번호를 다시 꺼내 붙여야** 합니다.
**안 건드려도 될 값을 건드리게 됩니다.**

★**S3 키 2개를 한 통에 두는 것은 묶는 게 아닙니다** — 액세스 키와 보안 키는
**한 자격증명의 양쪽 절반**이라 항상 같이 발급되고 같이 폐기됩니다.

### ① `catchap-database-url`

```
설명 (52자)
백엔드 DB 접속 URL (계정·비밀번호 포함). 바뀌면 API 전체가 DB 연결 실패로 죽음

시크릿 값 — 1행
키   DATABASE_URL
값   ★제가 클립보드에 넣어 드립니다 (177자)
     mysql+pymysql://catchap_backend:…@az-b.mysql-team1.{프로젝트ID}
       .mysql.managed-service.kr-central-2.kakaocloud.com:3306/catchap?charset=utf8mb4
```

★**제가 조립하는 이유** — 비밀번호를 URL 안에 넣으려면 특수문자를 인코딩해야 합니다.
예전에 `@` 를 그대로 뒀다가 접속이 안 된 적이 있습니다(`@` → `%40`).
**이번 비밀번호는 16자이고 인코딩이 필요한 문자가 없었습니다**(인코딩 전후 길이 동일).

#### ★★0805 정정 — IP 를 쓰려다 콘솔을 보고 바꿨다

사장님 지시 — *"규칙으로 추론 하지 말고 값부터 먼저 확인해보자"* · *"카카오클라우드에
등록되어 있는걸 먼저 확인하자"*. **그 지시가 실제로 하나를 잡았습니다.**

```
처음 만든 값   …@10.0.2.193:3306/catchap        ← 캡차 ConfigMap 에 있던 IP 를 그대로 씀
콘솔 정본      az-b.mysql-team1.{프로젝트ID}.mysql.managed-service.kr-central-2.kakaocloud.com
```

★**`10.0.2.193` 은 az-a 노드(오늘 Standby)의 IP** 입니다. 지금도 붙지만 **인스턴스가
교체되면 바뀌고**, 보는 사람이 그게 MySQL 인지도 모릅니다.

★**역할을 정하는 것은 포트입니다 — `3306` 은 언제나 현재 Primary.** 호스트명(az-a/az-b)은
역할과 무관합니다(0731 `connection_id` 카운터로 확증 · 0803 수동 장애조치로 재확인).

                          ★catchap-database-url 하나면 팀원 DB 읽기 전용 제한이 무의미해집니다
✗ catchap-ci              배포 계정. 키가 VM2 에 상주 — 막는 것이 목적
✗ catchap-ops             지금도 KMS 층에서 막힘

## ★★시크릿을 나누는 기준 = 「같이 회전하는가」 (0805 확정)

사장님 질문 — *"난 각각 다 따로 하고 싶은데 실무에서는 이렇게 안 해?"*

**실무에서는 둘 다 씁니다. 가르는 기준은 하나입니다.**

```
묶는다   ★같이 회전해야 하는 값들. 갈라 두면 바꾸는 사이에 짝이 어긋난다
가른다   따로 회전하는 값들. 이름이 정확해지고 접근 제어·감사 기록이 값 단위로 갈린다
```

**그래서 이렇게 정했습니다.**

```
catchap-database-url           값 1개  ← 원래 하나
catchap-media-s3-keys    값 2개  ← ★한 자격증명의 양쪽 절반. 같이 발급·같이 폐기
```

⚠️**S3 키를 갈라 두면 안 되는 이유** — 액세스 키만 새 버전으로 바꾸고 보안 키를 아직
안 바꾼 순간에 **인증이 조용히 실패**합니다. 로그에는 `403` 만 남고 이유가 안 나옵니다.

### ★기존 5건 점검 결과

```
catchap-auth-jwt-secret        값 1개 · 단독 회전   ○ 그대로 좋다
catchap-smtp-app-password      값 1개               ○
catchap-metrics-ingest-token   값 1개               ○
catchap-stt-worker-token       값 1개               ○
catchap-portone-keys           값 2개               ○ ★이름·재생성 다 불필요 (아래 정정 참고)
```

### ★★이름 규칙 — 「시크릿 이름 = 안에 든 환경변수 이름」 (0805 확정)

사장님 질문 — *"이름은 변경 안 해도 돼? 기존 이름들"* 로 대 봤더니 **규칙이 있었습니다.**

```
catchap-smtp-app-password     ←  SMTP_APP_PASSWORD      ★정확히 일치
catchap-metrics-ingest-token  ←  METRICS_INGEST_TOKEN   ★정확히 일치
catchap-stt-worker-token      ←  STT_WORKER_TOKEN       ★정확히 일치
catchap-auth-jwt-secret       ←  JWT_SECRET_KEY         △ auth- 를 붙이고 -key 를 뺌
```

★**이 규칙이 좋은 이유** — 이름만 보고 **어떤 환경변수가 들었는지** 압니다.
`portone-keys` 가 헷갈렸던 게 정확히 이 규칙을 안 지켜서였습니다.

**그래서 새 이름을 `catchap-db-url` → `catchap-database-url` 로 바꿨습니다**(사장님 선택 A).

★**`catchap-auth-jwt-secret` 은 규칙에서 살짝 벗어나지만 그대로 둡니다** —
JWT 시크릿은 프로젝트에 하나뿐이라 헷갈릴 여지가 없고, **이름은 수정 불가라 재생성해야 하는데
값을 눈으로 옮겨야** 합니다. **얻는 게 「이름이 조금 더 규칙적」뿐이라 값어치가 없습니다.**

**앞으로 늘어날 것도 같은 규칙으로**

```
catchap-main-captcha-site-secret   ←  MAIN_CAPTCHA_SITE_SECRET   ★배포 직후 필요
```

### ★★정정 — `catchap-portone-keys` 는 ★재생성도 이름 변경도 필요 없습니다 (0805)

처음에 *"재생성이 맞다"* 고 적었는데 **과하게 쪼갠 것이었습니다.** 사장님 질문 —
*"그러면 포트원은 하나 있는거지? 그러면 이름 안 바꿔도 되는거야?"* 로 다시 봤습니다.

**갈라야 할 선은 「공개냐 비밀이냐」 하나입니다.**

```
PORTONE_STORE_ID        공개  → ConfigMap
PORTONE_CHANNEL_KEY     공개  → ConfigMap
─────────────────────────────────────────
PORTONE_API_SECRET      비밀  ┐ ★둘 다 포트원 콘솔에서 나오는 서버 전용 자격증명
PORTONE_WEBHOOK_SECRET  비밀  ┘   포트원 계정이 털리면 ★둘 다 새로 받는다 = 같이 회전
```

★**내가 *"발급처가 달라 따로 회전한다"* 고 했는데, 그건 발급 절차 이야기였지 회전 이유가
아니었습니다.** 쪼갤 근거가 약했습니다.

**그래서 이렇게 됩니다.**

```
지금  v1  PORTONE_API_SECRET · PORTONE_CHANNEL_KEY      ← 공개값이 섞여 있음
나중  v2  PORTONE_API_SECRET · PORTONE_WEBHOOK_SECRET   ← ★비밀 2개. 이름 "keys" 가 맞음
```

★**이름·설명 그대로 씁니다.** `keys` 는 복수이고 **서버용 키 2개**를 정확히 가리킵니다.

★★**버전 추가가 재생성보다 안전합니다** — 재생성은 **값을 눈으로 보고 옮겨야** 하지만,
버전 추가는 **기존 값을 손 안 대고** `WEBHOOK_SECRET` 만 더하면 됩니다.

### 참고 — 왜 공개값이 금고에 들어갔나

이미지 안 `app/core/config.py` 주석이 그대로 말해 줍니다.

```python
PORTONE_STORE_ID        # store-xxxxxxxx (공개)
PORTONE_CHANNEL_KEY     # channel-key-xxxxxxxx (공개) — 콘솔 결제연동>채널관리에서 발급
PORTONE_API_SECRET      # V2 API Secret — ★절대 프런트로 노출하지 않는다
PORTONE_WEBHOOK_SECRET  # 웹훅 서명 검증용(선택)
```

★**코드가 앞의 둘을 실제로 프론트로 내려보냅니다** (`payments.py:273·274·372·373`).
그런데 시크릿 안에는 **`PORTONE_API_SECRET`(비밀) 과 `PORTONE_CHANNEL_KEY`(공개)** 가
같이 들어 있습니다. **공개값을 금고에 넣을 이유가 없고, 그것 때문에 이름이 `keys` 로
뭉뚱그려져 0805 에 나를 헷갈리게 했습니다**(있는 줄 알았던 2개가 없었음).

**올바른 모양** (위 정정 반영)

```
ConfigMap (비밀 아님)     PORTONE_STORE_ID · PORTONE_CHANNEL_KEY
catchap-portone-keys      PORTONE_API_SECRET · PORTONE_WEBHOOK_SECRET   ★이름 그대로
```

### ⬜ 언제 할까 — ★지금은 아니다

```

           ② STORE_ID·WEBHOOK_SECRET 값은 아직 모른다 (포트원 콘솔에서 받아야 함)

```

② WEBHOOK_SECRET 을 받아 ★버전 2 생성        기존 값은 손 안 댄다

## 만든 뒤 — 배포에 반영할 것

`SECRETS_NAMES` 에 이름 **두 개**를 더 적어야 로더가 읽습니다(안 적으면 무시됩니다).

```
k8s/backend/10-configmap.yaml
  SECRETS_NAMES: "…기존 5건…,catchap-database-url,catchap-media-s3-keys"
```

★**전부 긁지 않고 배포가 명시**하게 돼 있습니다. 그래야 남이 만든 시크릿까지 읽으려
들지 않고, 시크릿이 하나 늘었을 때 앱 동작이 말없이 바뀌지 않습니다.

**확인 방법** — 값을 안 보고 이름만으로 확인할 수 있습니다.

```
docker run --rm --env-file /tmp/sm.env --entrypoint python <백엔드이미지> -c \
  'from app.core.secrets_loader import load_secrets_into_env as L; r=L(); print(len(r.loaded), sorted(r.loaded))'
→ ★9개가 나와야 합니다 (기존 6 + 이번 3)
```
