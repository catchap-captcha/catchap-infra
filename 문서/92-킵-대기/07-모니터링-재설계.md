## 2. ★새 환경에서 깨지는 자리 다섯 — 전부 실측

### ① 기대 서버 목록이 옛 VM 이름

### ② ★백엔드 self-collect 가 두 파드에서 같은 행을 덮어씁니다

같은 순간에 두 파드에서 직접 재 봤습니다.

```

→ 화면 값이 **요청마다 튑니다.** 어느 파드가 응답했느냐에 따라 달라집니다.

### ③ ★psutil 이 파드가 아니라 노드를 봅니다

```
파드가 보고한 mem_total = 15,993 MB
노드 실제 용량          = 16,377,056 Ki ≈ 15,993 MB   ★정확히 같음

cgroup 제한을 안 보기 때문입니다. 즉 "backend 카드" 는 실제로는 **그 파드가 앉은 노드**를 보여줍니다.
★나쁘기만 한 건 아닙니다 — **노드 지표를 덤으로 얻고 있는 셈**입니다. 다만 **이름이 틀렸고 두 노드가 한 칸에서 뒤섞입니다.**

### ④ ★self-collect 는 「누가 화면을 열어야」 갱신됩니다

`backend` 행이 **8일 전**인 이유입니다. 아무도 안 열었습니다.
→ 배경 수집이 없으면 추이 그래프에 구멍이 납니다.

### ⑤ ★관리형 MySQL 엔 에이전트를 넣을 방법이 없습니다

### ★★★실측 — 필요한 것은 **`reader` 역할 하나**입니다 (확정)

세 가지 키로 차례로 재서 원인을 좁혔습니다.

```
가짜 키 · 헤더 없음        → 400 Bad Request      형식 단계에서 거절
S3 자격증명(MEDIA_S3_*)   → 403 + ★HTML 본문     자격증명 종류가 다름
catchap-backend IAM 키    → 403 + ★JSON 본문
     {"error":"failed to get role (reader) in x-kep-roles"}
★catchap-ci IAM 키        → ★200  (ke·mysql·memstore·server·lb ★다섯 다)
```

★**오류 본문이 무엇이 없는지 그대로 말해 줍니다 — `reader` 역할.**
`catchap-ci` 는 `[member reader load-balancer_member]` 를 갖고 있어서 통과했고,
`catchap-backend` 는 그게 없어서 막혔습니다.

★★**즉 코드도 경로도 헤더도 다 맞습니다. 계정에 역할 하나만 붙이면 됩니다.**
