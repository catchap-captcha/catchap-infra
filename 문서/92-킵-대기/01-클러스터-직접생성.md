# 킵 — 클러스터 직접 생성 (승인 받음 · 대기)

**목적** — 우리가 만든 클러스터에서는 우리가 관리자가 되는지 확인한다.
맞으면 `cluster-admin` 이 풀리고 **배포·자동화·Argo CD 가 한꺼번에 열린다.**

★사장님이 0803 승인받으심. 콘솔 작업이라 사장님이 누르시고 나는 값 확인·캡처·검증만 한다.

---

## 왜 이걸 하나

지금 `403` 하나가 이 전부를 막고 있다.

```
수동 배포 (kubectl apply)     cluster-admin 필요
배포 스크립트 자동화            같음
Argo CD (GitOps)              같음 — ClusterRole·CRD 를 만들어야 하니까
인그레스 컨트롤러 배포          같음
```

**가설** — 관리형 쿠버네티스는 대개 **만든 사람에게 관리자 권한**을 준다(GKE·EKS·AKS).
지금 프로젝트의 클러스터 3개가 **전부 강사님이 만드신 것**이고, 우리가 만든 걸
가져 본 적이 없다. 응답이 `401` 이 아니라 **`403`** 인 것도 *"인증은 되는데 명단에 없다"*
와 맞아떨어진다.

★**되돌리기가 완전하다** — 아니면 지우면 만들기 전과 똑같아진다.
강사님 클러스터는 **건드리지 않는다**(새로 만드는 것이지 지우는 게 아니다).

---

## 넣을 값 — 기존 `catchap-cluster-prod` 와 맞춘다

### 1) 클러스터

| 항목 | 값 | 근거 |
|---|---|---|
| 이름 | `catchap-cluster-test` | 4~20자·영문 소문자/숫자/하이픈. ★기존과 헷갈리지 않게 `-test` |
| 설명 | `권한 확인용 임시 클러스터 — 확인 후 삭제` | 60자 이내. ★**왜 두 개인지**가 보이게 |
| Kubernetes 버전 | `1.33` | 기존과 동일 |
| VPC | `Team1-VPC` | |
| 서브넷 | `catchap-core-2a` + `catchap-core-2b` | 기존과 동일(AZ 이중화) |
| **엔드포인트** | ★**프라이빗** | ★★**기본값은 퍼블릭이다.** 강사님이 일부러 프라이빗을 고르셨으니 그대로 따른다 |
| CNI | `Calico` | 기본값 |
| 서비스 IP CIDR | **비워 둔다** | ★기존이 무엇인지 화면에 안 나온다. 양쪽 다 비우면 같은 기본값이 들어간다 |
| 파드 IP CIDR | **비워 둔다** | 같음 |

★화면 안내: *"클러스터 생성 후에는 서비스 IP와 파드 IP를 변경할 수 없습니다"* ·
`198.18.0.0/16`(Kubernetes Engine 내부용)과 겹치면 안 됨.

### 2) 노드 풀 — 클러스터를 만든 뒤 따로 만든다

기존 `catchap-nodpol-prod` 값:

```
인스턴스 유형   m2a.xlarge        (4 vCPU · 16GB — 전체 8 vCPU · 32GB 에서 역산)
디스크          100 GB
노드 수         2 (고정 · 오토스케일링 미사용)
가용 영역       kr-central-2-a 와 -b 에 하나씩
키 페어         Team1-Key         ★워커에 SSH 가 된다
```

★**권한 확인만 할 거면 노드는 1개, 더 작은 유형으로도 된다.**
`kubectl get ns` 가 되는지 보는 데는 노드가 필요 없을 수도 있다
(apiserver 는 노드와 별개다). **노드 없이 먼저 확인**해 보는 게 가장 싸다.

## 확인 절차 (내가 실행)

```
① kubeconfig 파일 받기        클러스터 목록 상단 [kubeconfig 파일]
② VM1 에서 kubectl 시도       curl 로 apiserver 에 IAM 토큰을 던져 본다
      GET /api/v1/namespaces
      403 → 가설이 틀림. 지운다.
      200 → ★풀렸다. 기존 클러스터에도 같은 방법을 쓸 수 있는지 본다
③ 결과와 무관하게 기록          왜 됐는지/안 됐는지가 다음 판단의 근거다
```

★**기존 클러스터에서 403 이 나던 것과 같은 방법으로 재야 한다.**
다른 방법으로 재서 다르게 나오면 그건 권한이 아니라 방법 차이다(오늘 여러 번 겪었다).

## 끝나면

```
가설이 맞으면   → 기존 catchap-cluster-prod 를 계속 쓸지, 새것으로 옮길지 정한다
                  ★기존 것에 우리를 추가할 방법이 생길 수도 있다
가설이 틀리면   → 즉시 삭제하고 강사님 답을 기다린다
어느 쪽이든     → 임시 클러스터는 오래 두지 않는다 (프로젝트에 우리 클러스터가
                  둘이면 나중에 어느 게 진짜인지 헷갈린다)
```
