## 1. 두 갈래 — 왜 (나)를 골랐나

| | (가) Actions + self-hosted runner | **(나) GitOps (ArgoCD)** |
|---|---|---|
| 부품 | 러너 1개 | ArgoCD + 매니페스트 저장소 |
| 준비 | VM2 가 이미 다 갖춤 | 새로 배우고 운영 |
| 배포 이력 | Actions 로그 | ★git — `git revert` 로 되돌림 |
| 손으로 고친 것 | 그대로 남음 | ★git 과 다르면 되돌려 놓음 |
| **CD 권한** | ★러너에 `cluster-admin` 키 상주 | ★**러너에 클러스터 권한 불필요** |

### ★★★0805 저녁 — (나)를 고를 근거가 하나 더 생겼습니다

**`catchap-ci` 의 권한을 RBAC 으로 좁히려다 ★안 되는 것을 확인했습니다.**

```
가짜 사용자로 잰 시험     필요한 것 12개 yes · 못 해야 할 것 5개 no   ← 완벽
cluster-admin 삭제 후     ★막혀야 할 3개가 여전히 됩니다
```

**원인** — 클러스터 신원에 IAM 역할이 실려 오고, 그게 RBAC 위에서 통과시킵니다.

```
Extra: alpha.kubernetes.io/identity/roles = [★member …]
```

★★**뗄 수도 없습니다** — CR 에 push 하려면 「프로젝트 멤버」가 필요한데
(Container Registry 전용 역할이 없음 · 실측 확정), 멤버이면 클러스터가 열립니다.

★**즉 「권한을 좁힌다」는 길이 막혀 있고, 「자격증명을 아예 안 둔다」만 남습니다.
그게 (나)입니다.** 자세한 것은 `00-작업기록.md` 37-19.

---

★★**결정적인 차이는 마지막 줄입니다.**

```
(가)      키가 VM2 파일에 있음  →  ★그 서버에 들어가면 밖으로 들고 나갈 수 있음
(나)      클러스터 안 ServiceAccount  →  ★들고 나갈 수 없음
```

★**「특권을 가진 것이 없어진다」가 아니라 「특권이 서버 파일에 놓인 열쇠가 아니게 된다」** 입니다.
그리고 이것이 **`catchap-ci` 의 `cluster-admin` 을 좁히는 문제를 구조적으로 해결**합니다.

## 2. ★git 에 비밀값은 안 올라갑니다

```
★올린다     Deployment · Service · Ingress · ConfigMap
★안 올린다   Secret 의 실제 값 — 지금처럼 금고나 kubectl 로 넣습니다
```

★**우리 파일이 이미 그렇게 돼 있습니다** — `20-secret.예시.yaml` 이라는 이름이고
안에 값 대신 `"여기에-넣지-말-것"` 이 적혀 있으며, 만드는 명령이 주석에 있습니다.

### ⚠️함정 둘

```
① ArgoCD 의 청소(prune)
   설정에 따라 "git 에 없는 것은 지운다" 로 동작 → ★손으로 만든 Secret 을 지웁니다
   대책: Secret 을 관리 대상에서 빼거나 청소를 끕니다. ★설치할 때 정해야 합니다

② 실수로 커밋
   ★지우고 다시 커밋해도 기록에 남습니다
   대책: .gitignore 에 .env · *secret*.yaml · 커밋 전 검사(pre-commit)
```

★**0805 에 실제로 겪은 것** — `_ms-captcha-extract/drag-captcha/.env` 에 캡차 비밀값이
평문으로 있었습니다. **저장소에 안 올라가 있어서 다행**이었고, 그래서 **컷오버 때 회전**합니다.

## 3. ⬜정해야 할 것 — `main` 고정 외에 여섯 개

사장님 결정: **배포 브랜치 = `main`.** 이전 작업이 끝나면 그 코드가 `main` 이 됩니다.

### ① ★누가 `main` 에 넣나 — 가장 중요합니다

```
자동배포가 붙으면 ★"main 에 들어간 것 = 곧 프로덕션" 입니다
→ 직접 push 금지 · PR 필수 · 리뷰 최소 1명
```

★★**staging 환경이 없습니다.** 지금은 사람이 배포를 눌러 한 번 걸러지는데,
자동화하면 그 단계가 사라집니다. **PR·리뷰가 유일한 안전장치가 됩니다.**

⬜나중에 네임스페이스를 하나 더 만들어 staging 을 둘 수 있습니다(클러스터는 그대로).

### ② 이미지 태그 = 커밋 해시

```
지금 우리 태그 4개 중 ★3개가 이미지 ID 입니다 — 어느 커밋인지 모릅니다
  backend 79d5e2d05a1e · frontend 488c549a0b53
  behavior-ai feea9a597269 · captcha d519323cdfe0
★0805 저녁 기준 넷 다 이미지 ID 입니다 — 커밋으로 가리킬 수 있는 것이 하나도 없습니다
★latest 금지 — 무엇이 떠 있는지 알 수 없게 됩니다
```

### ③ 매니페스트를 어디에

```
(가) 각 앱 저장소 안 k8s/ 폴더   ★권함. 코드와 배포 설정이 한 PR 에. 5명 팀엔 단순
(나) 별도 저장소                앱 개발자가 배포를 몰라도 됨. 저장소가 하나 늘어남
```
⚠️인그레스처럼 **여러 앱이 공유하는 것**은 둘 곳이 애매합니다 — 따로 정해야 합니다.

### ④ ★캡차 저장소 신설

```
지금   소스가 옛 GPU 서버 /srv/codex-workspaces/ms/swc 에만 있습니다
       ★git 저장소가 없어 "어느 버전인지" 를 파일 크기로 비교했습니다(0805)
```
★**이것 없이는 캡차만 자동배포에서 빠집니다.** ms님과 정리해야 합니다.

### ⑤ CI 가 검사할 것

```
최소   빌드가 되는가        ← 이것만 해도 값이 큽니다
다음   테스트 · 린트
```
★**검사가 없으면 「CI」가 아니라 그냥 자동 배포입니다.**

### ⑥ 되돌리는 방법

```
GitOps   git revert  →  ArgoCD 가 알아서 되돌림
지금     kubectl rollout undo
```
