민서님, 답변 감사합니다. ② 진행하기로 해서 인프라 쪽을 먼저 깔아 뒀습니다.

■ 해 둔 것 — 민서님이 하실 일 없습니다

  · 금고 시크릿 catchap-valkey-auth 만듦 (VALKEY_PASSWORD)
  · 캡차 ConfigMap 에 접속 설정 병합 (catchap-infra PR #43·#44)
  · 파드 재기동해서 로더가 시크릿 7건 읽는 것 확인
  · 실제로 Valkey 에 붙여서 확인 — AUTH +OK / PING +PONG / DBSIZE :0
  · CA 인증서 받아 둠 (필요해지면 저희가 마운트합니다)

  코드에서 os.environ 만 읽으시면 바로 붙습니다.

    VALKEY_HOST / VALKEY_READ_HOST / VALKEY_PORT
    VALKEY_USERNAME(=catchap) / VALKEY_PASSWORD(금고에서 자동 주입)
    VALKEY_TLS(=true) / VALKEY_TLS_SERVER_NAME

■ 붙일 때 함정 두 개 — 제가 다 겪었습니다

  ① AUTH 는 두 인자입니다. 한 인자로 보내면 default 사용자로 붙어 -WRONGPASS 납니다.
     콘솔 접근 제어의 "DB 사용자 이름"이 catchap 입니다.

  ② TLS 의 server_hostname 은 엔드포인트가 아니라 인증서 CN 을 줘야 합니다.
     (service.kakaoenterprise.com) 서버 인증서에 subjectAltName 이 없어서,
     엔드포인트 이름으로 붙으면 Hostname mismatch 로 거부됩니다.

  CA 파일은 민서님이 챙기실 필요 없습니다. 코드는 경로만 읽으시면 되게
  저희가 ConfigMap 으로 마운트하겠습니다. 원하시는 경로 있으면 말씀만 주세요.

■ 먼저 정정 — 제가 착각했던 것

  제가 처음에 "임시 상태를 캐시로 옮기면 CASCADE 위험이 사라진다"고 했는데
  엄밀히는 틀렸습니다. 민서님 말씀대로 챌린지 행 자체는 DB 에 남으니,
  그 행을 지우면 여전히 연쇄됩니다.

  진짜 해결은 "지우는 게 안전해지는 것"이 아니라 "지울 이유가 없어지는 것"입니다.
  만료·정답이 캐시에 있으면 DB 행은 기록으로만 남고, 2.41MB 는 그냥 둬도 됩니다.
  청소 자체가 필요 없어집니다.

■ 설계 초안 요약

  옮길 것   정답 좌표·임시 ID 매핑 / 만료 판정 / 레이트리밋 4종 / 토큰 유효성
  둘 것     챌린지 행 / attempts / behavior_batches (기록·학습)
  조심할 것 receipt-chain 머리 (next_batch_seq, last_receipt_hash)

  가장 큰 이득은 레이트리밋입니다. request_pattern() 이 챌린지마다 질의 4개를
  도는데 (둘은 표 2~3개 JOIN), 캐시 INCR+EX 로 옮기면 4개 → 0개가 됩니다.

  캐시가 죽었을 때가 설계의 핵심이라고 봅니다.
    레이트리밋  → DB 질의로 되돌아간다 (못 세면 무제한 허용이 되므로)
    정답 좌표   → 그 챌린지는 만료 처리 (새로 내주면 됨)
    토큰 유효성 → DB 조회로 되돌아간다
  "캐시가 죽으면 통과시킨다"는 절대 안 됩니다. 캐시를 죽이는 게 곧 우회가 됩니다.

  옮기는 순서는 레이트리밋 → 토큰 → 정답 좌표 → (사슬 머리) 로 제안드립니다.
  1단계에서 캐시 카운터와 DB 질의를 며칠 같이 돌려서 값이 얼마나 다른지
  숫자로 보고 한도를 정하면 좋겠습니다.

■ 여쭙고 싶은 것 여섯 가지

  ① 레이트리밋은 고정 창으로 충분할까요? 슬라이딩이 필요할까요?
  ② receipt-chain 머리는 (가)안 두기 / (나)안 write-through / (다)안 캐시만
     — 어느 쪽이 좋을까요? 저는 (가)안을 추천드립니다.
     캐시가 사슬 머리를 잃으면 그 세션 행동 데이터가 통째로 버려져서요.
  ③ "캐시가 죽으면 DB 로 되돌아간다"에 동의하시나요?
  ④ 이행 순서가 이대로 괜찮을까요? 1단계 양쪽 비교는 어떠신지?
  ⑤ 키 이름 규칙(rl:ip:… rl:sess:…)을 이렇게 가도 될까요?
  ⑥ CA 마운트 경로는 /etc/valkey/ca.crt 로 할까요?

  SECRETS_REQUIRED_VARS 에는 일부러 안 넣었습니다. 넣으면 코드가 쓰기도 전에
  기동 조건이 되어 버려서요. 실제로 쓰기 시작할 때 같이 넣겠습니다.

■ 덤으로 찾은 것 — 배포 중 502 (민서님 배포에도 영향)

  파드가 뜨는지 확인하려고 재기동하며 두드려 봤더니 90번 중 3번 끊겼습니다.
  (502 두 번, 연결 끊김 한 번) 파드가 종료 표시되는 것과 인그레스가 대상에서
  빼는 것이 동시가 아니어서, 그 틈에 온 요청이 갈 곳을 잃는 것이었습니다.

  다섯 서비스에 preStop: sleep 5 를 넣어 고쳤습니다 (PR #45).
  다시 재서 130번 중 0번입니다. 캡차 배포도 조금 더 조용해집니다.

  0804 매니페스트 주석에 "안 끊긴다"고 적혀 있었는데 사실이 아니었습니다.
