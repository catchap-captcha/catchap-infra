# 권한 시험 기록

**무엇을 시험했고, 왜 그렇게 결정했는지**를 남깁니다.
계정을 지우거나 역할을 바꿀 때마다 여기에 한 줄씩 추가합니다.

★ 카카오클라우드 서비스 계정은 **역할을 나중에 못 바꿉니다.** 그래서 "왜 이 역할인가"를
기억으로 갖고 있으면 안 됩니다. 사람이 바뀌거나 시간이 지나면 같은 시행착오를 반복합니다.

# 2026-07-29

### 서비스 계정 역할은 변경 가능한가

- **시험**: 콘솔에서 서비스 계정 상세·목록의 역할 편집 경로를 찾음
- **결과**: **불가**
  - 계정 상세에 역할 추가·수정·삭제 UI가 **없음**. `프로젝트 역할` 옆 `설정`은
    표 표시 설정(페이지당 개수·줄바꿈)일 뿐
  - 목록의 `서비스 계정 생성`·`설정`·`삭제`는 사장님 계정에서 **전부 비활성**(행 선택과 무관 = 권한)
  - **멘토님 확인: "역할 추가·삭제 불가. 계정을 지우고 다시 만들어야 한다"**
- **결정**: 명세를 한 번에 맞춘다. 확신 없는 항목은 **새 계정을 먼저 만들어 검증한 뒤
  기존 것을 지우는 순서**로 간다. 동작 중인 계정을 먼저 지우지 않는다.

### ★사장님 계정은 조직 관리자였다 — 프로젝트 역할이 없었을 뿐

- **시험**: 콘솔 `계정 설정 → 조직 역할 / 프로젝트 역할` 확인 (비밀번호 재입력 필요)
- **결과**
  ```
  조직 역할     조직 관리자 (Admin) · Alert Center 조직 매니저
  프로젝트 역할  없음
  ```
- **왜 중요한가**: 지금까지 콘솔에서 수정 버튼이 전부 비활성이었던 이유가 이것.
  **권한이 없어서가 아니라 프로젝트 역할이 없어서**였다.
- **그리고**: 조직 관리자 역할 설명에 **"사용자 및 IAM 역할을 추가 또는 삭제할 수 있습니다"**.
  권한 없음 안내 화면에도 **"조직 관리자: IAM > 사용자 메뉴에서 본인 계정에 프로젝트 역할을
  직접 할당해 주세요"**라고 되어 있음
- **결정**: **프로젝트 역할 할당은 멘토님 없이 사장님이 직접 할 수 있는지 먼저 확인한다.**
  된다면 요청 항목 여러 개가 사라진다
- **미확인**: 본인에게 `프로젝트 관리자`를 할당하면 **서비스 계정 생성·보안그룹 수정·버킷 권한**까지
  풀리는지. 풀린다면 멘토님께 부탁드릴 일이 대폭 줄어든다

# 2026-07-30 새벽 — 공식 문서로 해결된 것

### ★`Secrets Manager 뷰어`는 시크릿 값을 못 읽는다 — 확정

- **출처**: [Secrets Manager 주요 개념](https://docs.kakaocloud.com/service/security/secrets-manager/secrets-manager-main)
- **원문**
  > **Secrets Manager 뷰어(Viewer)**: 시크릿의 목록, 상태, 버전 정보 등 리소스를 조회할 수 있는
  > 권한을 가집니다. **단, 시크릿 값을 조회하거나**, 시크릿 생성 및 상태를 변경하는 등
  > 암호화 또는 관리 작업은 **수행할 수 없습니다.**

  > **Secrets Manager 매니저(Manager)**: … 단, 시크릿 암호화에 필요한 KMS 키 사용을 위해서는
  > **KMS 사용자(User) 역할 이상이 필요**합니다.
  > 주의: 시크릿 생성, KMS 키 변경, 버전 생성, **시크릿 값 조회** 등 KMS 키를 사용해
  > 암호화·복호화를 할 수 있는 **KMS 사용자(User) 역할 이상이 추가로 필요**합니다.
- **결정**
  - 앱 계정은 **`Secrets Manager 매니저` + `KMS 사용자`** 로 확정
  - **`catchap-app` / `catchap-app-b` 예비 쌍 계획 폐기.** 시험할 필요가 없어짐
  - **`catchap-backend`가 이미 정확히 그 조합**(Object Storage 매니저 · KMS 사용자 ·
    Secrets Manager 매니저)이므로 **새 계정을 만들지 않고 그대로 사용**
- **교훈**: 계정을 두 벌 만들어 시험하자는 계획을 세우기 전에 **문서를 먼저 읽었어야 했다.**
  "문서에 안 나온다"고 판단했던 것은 `IAM 역할 문서`만 봤기 때문이고,
  **각 서비스의 `주요 개념` 문서에 역할별 상세 권한이 따로 적혀 있었다.**

### ★Object Storage는 IAM 역할만으로 객체 접근 불가 — 확정

- **출처**: [Object Storage 주요 개념](https://docs.kakaocloud.com/service/storage/object-storage/object-storage-main)
- **원문**
  > IAM에서 프로젝트 관리자·멤버·뷰어·Object Storage 매니저·뷰어 역할은
  > **최초에 버킷에 대한 생성 및 목록 조회에 대한 권한만** 가질 수 있습니다.
  > 다만 버킷을 생성하게 되면 **버킷 생성 시 초기 역할 정보에 따라 Object Storage 역할이 버킷에 부여**됩니다.
- **버킷 생성 시 자동 부여되는 역할**
  ```
  프로젝트 관리자        → storage.admin      (FULL_CONTROL)
  프로젝트 멤버          → storage.editor     (READ+WRITE)
  Object Storage 매니저  → storage.editor     (READ+WRITE)
  Object Storage 뷰어    → storage.viewer     (READ)
  ```
- **의미**: `catchap-backend`가 지금 업로드·다운로드되는 이유는 **그 계정이 버킷을 직접 만들어서**
  `storage.editor`를 자동으로 받았기 때문. **새 계정은 그 혜택이 없다.**
- **결정**: 새 계정을 쓸 경우 버킷 권한에 **`storage.objectAdmin`**(객체만 관리) 추가 필요.
  → **`catchap-backend`를 그대로 쓰면 이 요청 자체가 불필요**
