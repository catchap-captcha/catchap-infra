# MemStore 클러스터 재생성 — 작업 계획과 캡처 목록

작업일 2026-08-03 · 인프라 김태형
목적: **사용자 인증이 꺼진 채 만들어진 Valkey 클러스터를 인증 켜서 다시 만든다.**

---

## 왜 하는가 (한 줄)

`catchap-redis-prod`는 **사용자 인증·전송 암호화가 둘 다 꺼져** 있고,
이 둘은 **생성할 때만 정할 수 있어** 지금 클러스터로는 못 켠다.
데이터가 0건인 지금이 다시 만들기 가장 싼 시점이다.

### 근거 3개 (전부 실측)

| 확인처 | 결과 |
|---|---|
| 콘솔 상세 액션 | 자동 백업 설정·백업 생성·파라미터 그룹 변경·보안 그룹 수정·노드 유형 변경뿐 — **접근 제어 수정 없음** |
| 콘솔 생성 마법사 | **3단계 「고급 설정 — 접근 제어, 백업」** 에 있음 = 생성 시 설정 |
| API 문서 | 클러스터 **수정 엔드포인트 자체가 없음** (GET 5개 + 파라미터그룹 재적용 1개) |

### 지금 위험이 없다는 근거

- `DBSIZE` = **0** (VM1에서 직접 확인)
- 자동 백업 6개의 **백업 파일 크기 175 Bytes** — 담긴 게 없다
- 모니터링 1시간: `get`·`set`·`del` 전부 **0회**, 활성 커넥션 2개(복제·헬스체크)

## 순서 — ★만들고 나서 지운다

지우고 만들다 생성이 막히면(권한·쿼터) **서비스가 사라진 채로 남는다.**
반대로 하면 실패해도 잃는 게 없다.

```
① 새로 만든다   catchap-valkey-prod   (인증 ON · TLS ON)
② 검증          인증 없이 거부되는가 · 인증하면 되는가
③ 옛것을 지운다 catchap-redis-prod
④ 재검증        옛 주소가 정말 닫혔는가
```

★이름도 바로잡는다 — **Redis 가 아니라 Valkey** 다.
`catchap_dev_db`→`catchap`, `captcha_ms`→`catchap_captcha` 와 같은 맥락.

## 검증 계획 (내가 실행)

VM1(210.109.82.148) SSH 경유 · 읽기 명령만

1. **인증 없이 거부되는가** — `PING` → `NOAUTH ...` 가 나와야 한다
   (지금 클러스터는 `+PONG` 이 나온다 = 인증 없음)
2. **인증하면 되는가** — `AUTH catchap <pw>` → `+OK` → `PING` → `+PONG`
3. **TLS** — 평문 접속이 거부되는지
4. 옛 클러스터 삭제 후 **옛 주소가 닫혔는지**

★대조군을 반드시 같이 본다(관리형 MySQL 3306). 부정 결과가 나오면 측정기부터 의심한다.
