# 가비아 DNS·포워딩 확인 (2026-08-04 새벽)

★조회만 했습니다. **아무것도 바꾸지 않았습니다.**

## 1. catchap5.com 실제 레코드 — ★기록이 틀렸습니다

```
레코드 10개 · 최근 업데이트 2026-07-21 17:16 · 네임서버 ns.gabia.co.kr

A    @                  210.109.14.25     ★TTL 600
A    www                210.109.14.25     ★TTL 600
A    api                210.109.52.124    ★TTL 600
MX   @                  smtp.google.com.  우선순위 1
TXT  @                  SPF · google-site-verification
TXT  _dmarc             DMARC             ★0730 기록에 없던 것
TXT  google._domainkey  DKIM              ★없던 것
TXT  _acme-challenge    ×2                ★없던 것 (acme.sh DNS-01 흔적)
```

★**TTL 이 86400 이 아니라 600(10분)** 입니다.
0730 에 `dig` 로 본 86400 은 **SOA 의 기본값**이었고 레코드 TTL 이 아니었습니다.
→ **컷오버 롤백이 이미 10분.** TTL 낮추기 준비가 사실상 필요 없습니다.

★**메일 인증이 SPF 뿐 아니라 DKIM·DMARC 까지** 걸려 있습니다.
DNS 를 다른 곳으로 옮기면 이것들도 전부 옮겨야 합니다 — **옮기지 말자는 근거가 더 강해졌습니다.**

## 2. ★★포워딩은 우리에게 안 맞습니다

`catchap5.com` 에서 포워딩을 누르니 이 알림이 떴습니다.

> [DNS 설정] 서비스 이용중이거나 레코드 중복되어 설정이 불가합니다.
> [DNS 설정] 서비스를 해지하거나 중복 레코드 삭제 후 설정 가능합니다.

→ **루트에 A 레코드가 있으면 포워딩을 못 붙입니다.** 배타적입니다.

`muckgo.com`(레코드 0개)으로 설정 화면을 열어 보니 **구현 방식이 드러났습니다.**

```
포워딩 설정
  방식        고정 포워딩 / 유동 포워딩
  연결 주소    http:// | https:// 선택
  접속 통계    ON / OFF

★DNS 정보 — 포워딩을 켜면 자동 생성되는 레코드
  A  @     121.254.178.234   포워딩
  A  www   121.254.178.234   포워딩
```

★★**포워딩은 가비아 서버(`121.254.178.234`)를 가리키는 A 레코드로 구현됩니다.**

**그래서 HTTPS 가 안 됩니다.**

```
사용자가 https://catchap5.com 접속
  → 121.254.178.234 (가비아 포워딩 서버)
  → 그 서버가 catchap5.com 인증서를 갖고 있어야 한다
  → ★가비아가 우리 도메인 인증서를 가질 리 없다
  → 브라우저 경고
```

`http://` 는 되지만 요즘 브라우저는 HTTPS 를 먼저 시도합니다. **실질적으로 못 씁니다.**

★금액 표기가 없고 신청 화면이 바로 열린 것을 보면 **무료로 보이나, 무료여도 못 씁니다.**

## 3. 그래서 컷오버는 이렇게 합니다

```
catchap5.com   A      → 210.109.55.233  (catchap-lb-2a)
                        ★우리 LB 가 우리 인증서로 HTTPS 처리 · 인그레스가 www 로 301
www            CNAME  → catchap-lb-2ab-4957cfb14f.blb.kr-central-2.kakaocloud.com
api            CNAME  → 같음
```

★루트만 2-a 에 매이지만, 루트는 **www 로 넘기는 자리**라 영향이 작습니다.
`www`·`api` 는 고가용성 그룹이라 한쪽 영역이 죽어도 삽니다.

★**롤백은 A 레코드 값 하나 되돌리기**입니다. 포워딩 방식보다 단계가 적습니다.

## 4. 남은 것

- 인그레스에 `catchap5.com → www.catchap5.com` 301 규칙을 넣어야 합니다(Caddy 가 하던 일)
- 나중에 Cloudflare 검토 — 루트에 CNAME 을 쓸 수 있으나 **NS 이전이라 메일 위험**. 별건으로.
